# 1. A produção caiu, e a culpa foi minha

## O que você viu

```
Application error: a server-side exception has occurred
Digest: 713656032
```

## O que aconteceu, na ordem

1. Durante o dia apliquei no Supabase as migrations **007 a 013**. A última, a `013`,
   **derruba a tabela `aurea.custody_charges`**.
2. O código que fazia isso necessário ficou **só na minha máquina**. Os seis commits do dia
   nunca foram publicados — `origin/main` continuava em `f7a5e8c`.
3. A Vercel serve `origin/main`. Ou seja: **o site rodava um código que ainda lia
   `custody_charges`, contra um banco de onde eu já tinha removido a tabela.**

Conferido, não deduzido: o `account.ts` do commit publicado cita `custody_charges` quatro
vezes, e `to_regclass('aurea.custody_charges')` no banco devolvia `null`.

## Por que é culpa minha, e não azar

**Eu escrevi essa exata regra ontem, e hoje a quebrei.** Está em
`docs/diario/2026-09-11/LEITURA_REPOSITORIO_DETALHADO.md` e no relatório do Agente A:

> *Ordem obrigatória em qualquer ambiente novo: código primeiro, migration depois. Aplicar a
> migration antes de o código correspondente estar no ar derruba a aplicação inteira,
> inclusive o login.*

Apliquei a migration assim que terminei o código local, porque sem ela eu não conseguia
testar. O que faltou foi o passo seguinte: **publicar antes de migrar** — ou, no mínimo,
tratar o `git push` como parte da mesma operação, e não como um pedido no fim da mensagem.

## O que foi feito

`git push origin main` → `f7a5e8c..2cc7194`. A Vercel reconstruiu sozinha.

# 2. Um achado do check-up: o aviso de hidratação

No console de produção aparece `Minified React error #418` — falha de hidratação.

**Não é novo e não é defeito de hoje.** Vem do script anti-flash de tema, que existe desde
`ea0a5f3`, o commit do port original das doze telas. Ele escreve `data-theme` no `<body>`
**antes** de o React hidratar, justamente para a tela não piscar branco; o React percebe que
o DOM mudou e registra o aviso.

É **recuperável**: o React re-renderiza e a página funciona — todas as telas acima foram
lidas com o conteúdo certo. No servidor de desenvolvimento o aviso nem aparece.

Fica registrado como coisa a limpar quando alguém mexer em tema, não como urgência.

# 6. A regra que este dia deixou

**Publicar e migrar são a mesma operação, nesta ordem: `git push` primeiro, `db:migrate`
depois.** Separar os dois deixa a produção rodando contra um banco que ela não conhece, e o
sintoma — uma página branca com um código de digest — não se parece nem um pouco com a causa.

Eu tinha escrito essa regra ontem no diário. Escrever não bastou; ela precisa fazer parte do
mesmo comando.
